# Browser/Node Worker exceptional-effect boundary (candidate v1)

**Status: tested host transport only. NOT source-compiled Atto guest execution.**

This repository is the Wasm integration/backend, not the published Rust frontend.
The shipped `atto-lang.github.io/play` browser compiler remains SHA-pinned and
intentionally rejects source-level `defer`, `recover`, `raise` and `try/catch`.
See [AttoLang exception draft](https://github.com/atto-lang/atto-spec/pull/23)
and [the executable Rust/Wasm P0](https://github.com/atto-lang/atto-source.rs/issues/152).

The `runtime/terminal-effect-notice.mjs` adapter and its Node Worker tests
define a future **terminal guest-to-supervisor transport only**. It is not
loaded into the current public playground tenant or offered to Atto user
programs. It never interprets a JS `Error` or a Wasm engine trap as an
Atto `raise`, never sends a live `recover` callback, and does not perform
a remote `defer`. It requires a trusted guest runtime and compiler to resolve
catch/trap/recover/defer **inside the owning actor execution context**, then
emit a terminal notice only if the failure escapes that actor/task.

## Required effect routing

| Effect | In originating execution context | Across Worker boundary |
| --- | --- | --- |
| `throw Error` | Search full caller-chain typed catches/traps before eligible recover | If still unhandled: terminal CONTROL notice retaining `throw` |
| `raise Error` | Bypass catches/traps; run owned cleanup, then eligible recover | If still unhandled: terminal CONTROL notice retaining `raise` |
| `panic Error` | Bypass local catch/trap/recover; safe cleanup where possible | Terminal priority supervisor CONTROL notice retaining `panic` |
| cancellation, worker termination, host fault, OOM | Never converted into user `Error` / `recover` | Independent trusted-host termination/fault path, not guest notice |

A worker cannot send its stack, recover cursor, mutable state, outstanding
borrow or JavaScript exception object to its parent as an executable language
continuation. Structured-clone message fields are *data*, never proof of
cleanup, type validation or recovery eligibility. A signal generated by a
foreign Worker is not trustworthy merely because it claims `effect: panic`.

The receiver binds the *actual physical Worker* object, actor ID, parent ID,
generation, and one-shot terminal sequence. Old worker generations, duplicate
terminal signals, unknown effect categories, extra fields, forged recovery
claims and untrusted Worker sources fail closed. Only trusted runtime code
may create this notice; user-source imports never expose this API. A
transpiled JavaScript actor that can invoke unrestricted `postMessage`
cannot be considered to satisfy this trust boundary.

## Browser admission requirements before production integration

1. Version the guest/host effect ABI independently of legacy `atto.browser.guest.v2`. A v2 guest must never acquire this capability accidentally.
2. Native Rust and wasm32-compiled-Rust frontends must emit *real* matching guest instructions, with typed Error-subclass checks and separate ordinary/escalated effects.
3. Prove two-phase full dynamic catch search before recover, deferred cleanup LIFO exactly once, original return snapshot, one-shot cursor and owned failure metadata across await/suspends.
4. Each actor/task must perform guest unwind on its own live stack/continuation. A parent Worker may receive only a terminal failure. Force-terminated workers cannot promise `defer` ran; quiescence/reclaim must be explicit.
5. Supervisor CONTROL routing must retain effect identity and parent/child chain. Cancellation/host traps bypass language catch/recover; generation-fenced supervisor restart is separately required.
6. Run the **exact** `/play` preview sources through native and wasm32 compiler builds, execute resulting guest Wasm and JS-transpiled output, compare outcomes against Java/LLVM on verified SHAs, then authorize a reviewed public compiler release.
7. Test actual Browser Worker and Node Worker failure, replay, cancel, panic, transient host errors and resource quotas. A passing host transport test is **not** language backend parity.

## Reproduce this transport-only test

```sh
node --test tests/terminal-effect-notice.test.mjs
```

The test runs a real Node `worker_threads` structured-clone round trip as well
as negative notice validation. No Wasm guest, Rust compiler or JS transpiler
is invoked here. Source-level browser conformance remains **UNSUPPORTED**.

## Trusted terminal CONTROL snapshot hardening (2026-11-20)

At the Worker receiver boundary, supervisor terminal-effect records must be
validated as exact own data-descriptor snapshots before any actor identity,
generation, effect or message is consulted. `Object.keys` alone is insufficient:
it omits nonenumerable and symbol fields. Re-reading `record[field]` after a
descriptor check is a TOCTOU defect because a Proxy can return a different
value via its `get` trap. Sender and receiver now capture `Reflect.ownKeys`
and own enumerable data-descriptor values once, and use only the immutable
validated copy. Accessor, hidden, symbol, missing, unexpected and stale
fields are rejected. The receiver still binds the *actual* trusted Worker
object and one-shot actor generation; DATA envelopes and forged CONTROL
types cannot impersonate terminal notices.

Tests: `node --test tests/terminal-effect-notice.test.mjs
tests/terminal-control-snapshot.test.mjs` includes Proxy read-trap noninterference,
accessor denial, hidden/symbol authority rejection, DATA-vs-CONTROL separation
and replay rejection. This is a **host-only transport security gate**, not
compiled `.atto` actor messaging, supervisor guest unwinding, native AOT or
untrusted TenantVM containment. The terminal notice adapter is still not
wired to the shipped browser guest runtime or exposed as a guest import.

Do not mix this transport adapter with `src/send-receipt.mjs` DATA delivery
or `src/supervisor-stop-ledger.mjs` STOP authority; each has its own trusted
physical binding and lifecycle. Atto Wasm PR #50 retains the canonical
ActorArena frame/quiescence authority, and conformance #33/#40 own future
source-compiled typed-actor and CONTROL/response obligations. Real guest
execution and independent security review remain required for promotion.
