# Draft: fixed parameter bindings and SSA lowering (rebind v1)

Status: proposal only; no compiler implementation or execution claimed. Keep draft until reviewed and tested. Builds on [merged spec #223](https://github.com/atto-lang/atto-spec/pull/223) and [merged conformance #583](https://github.com/atto-lang/atto-platform-conformance/pull/583). The existing normative scope is the opt-in borrow-default profile; making it universal needs an explicit spec/profile migration decision. Do not silently change legacy semantics.

## Semantics

- Named formals in the borrow-default profile are fixed unless explicitly marked contextual `rebind` (type-first `rebind mut Foo f`; name-first `rebind f: mut Foo` where supported; scalar `rebind int n`). Keep existing identifiers named rebind legal. Reject duplicate marker, implicit receiver and bodyless formals.
- Fixed means the binding cannot be assigned, not that the referent is immutable, unique, non-null, or unaliased. `mut` and `take!` remain orthogonal. Rebind is callee-local; no caller slot write-back, signature/ABI change or overload distinction. Do not use it to manufacture ownership, noalias, readonly, or lifetime facts.
- Preserve type/access, lexical argument evaluation and checked loan provenance. On reassign evaluate RHS once; only on success replace, end old loan when legal or drop old owned value exactly once. Reject live invalidated reborrows, dangling replacement loans, ownership-inconsistent consuming paths and escaping local replacements. Track origin and drop facts at joins, unwind, cancellation and supported suspension. Never drop caller-owned incoming borrowed object. Fail closed for unsupported cases before artifact emission.
- Represent an unchanged incoming reference as a value in typed IR, not a writable reference cell. Ordinary nonescaping borrowing should introduce no heap box, deep copy, retain/release, tracing, or mandatory spill. Rebind can use SSA versioning/joins; only materialize storage for real addressability, ABI, suspension or other proven needs. Physical register moves, necessary GC roots, real spills and ordinary replacement allocation are not prohibited. Never remove runtime safety checks on the strength of fixed binding alone.

## Acceptance gates

1. Run the six shared fixtures from conformance #583 at a pinned revision, checking exact guest values or intended semantic diagnostic and no emitted artifact for rejection. Add backend cases for default fixed scalar/ref assignment, mutable referent without rebind, local scalar rebind, caller identity unchanged, contextual identifier, name-first round trip, duplicate marker, signature compatibility and overload collision, RHS failure, repeated replacement, mixed ownership joins, live reborrow, exit and supported unwind/cancellation.
2. Verify parser -> typed IR -> optimized target code; compare identical fixed and rebind-but-not-assigned functions, and a genuinely reassigned function. Check no binding-induced allocation/box/retain/release or avoidable memory slot in simple nonescaping fixed case; prove exact cleanup counts in replacement cases. Include an escaping/ABI-required control case to prevent unsafe blanket elision.
3. Benchmark matched Atto/Java scalar and object read, mutation and local reassignment workloads; same data, outputs, hardware, optimization tier and allocation policy; warm JVM JIT separately from cold/AOT runs, prevent dead-code elimination, record iterations, repetitions, median, dispersion, throughput, allocation/GC counts and code size. Publish raw measurements and toolchain versions. No promised speedup; Java already optimizes fixed and reassigned references. HDL and restricted profiles use their own meaningful metrics.
4. Record exact compiler and fixture revisions, commands, executed job IDs, diagnostics, IR/assembly and raw benchmark results. Unsupported vs not executed vs pass are distinct; source-only checks are not guest proof. Use source-owned or explicitly approved private CI only; no private export or bypass of release holds. No merge on the basis of this proposal.

## Backend-specific implementation and evidence

Use WebAssembly parameters and locals/SSA; avoid linear-memory shadow slots and guest retain/release for nonescaping loans; inspect WAT and guest allocation telemetry on browser and native runners. Host JS boundary costs counted separately.
